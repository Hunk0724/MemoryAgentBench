## 1. 最重要:GX10 弱模型是 **per-backbone gemma extraction**(非 held-fixed gpt-4o-mini)

matrix wrapper 設 `MEM0_TRIPLE_MODEL=gemma3:$SIZE` → **每個 backbone 用自己的 gemma 抽取**(各自 P1 cache `analysis/results/p1_caches__gemma3-{s}/`)。與 Mac 端「backbone=gpt-4o-mini 做整條 pipeline」是一致的類比 —— **backbone = 做整條 pipeline 的那個模型**。

**你整合時要改的描述**:CLAUDE.md / evaluation_protocol 把 ours_struct 寫成「held-fixed 共用 gpt-4o-mini extraction」;這對 **Mac(gpt-4o-mini)成立**,但對 **GX10 gemma 各 size 不成立**(是各自 gemma extraction)。paper 描述弱模型段時要講清楚。

**證據**:store 事實數 1b/4b≈370、12b/27b≈450;retrieved top-100 與 27b 重疊 1b=5、4b=82、12b=99(若 held-fixed 應全 ~100)。chunk `af9a27ef`:gemma-1b 抽 31 facts、gemma-27b 抽 38。

**含意(已寫進主分析檔)**:
- ✅ **同一 backbone 內方法比較公平**(struct/no_p5/p3_only/b 同 size 共用同一 extraction)→ 主 claim 靠 within-backbone gap,extraction 已控制。
- ⚠️ **跨 backbone 趨勢**混了 extraction + resolution(誠實的 on-device 故事)。
