# 2. Related Work

## 2.1 Proactive Approaches to Knowledge Update

Proactive approaches to KU attempt to resolve potential version conflicts at write-time, before they can accumulate in the memory bank. Within this paradigm, two sub-approaches are dominant, differentiated by how the LLM's role is structured relative to the actual memory mutation.

**Coupled Update.** In coupled-update designs—exemplified by Mem0 [5] and LightMem [3]—a single LLM call both decides the operation type (ADD / UPDATE / DELETE / NOOP) and triggers its execution against the memory bank. Mem0 implements this directly: the LLM receives a new incoming fact along with semantically related existing entries and emits an operation label that the system applies in place—an UPDATE label triggers vector and payload overwrite, and a DELETE label triggers hard removal. LightMem follows the same coupled pattern but introduces a sleep-time batching mechanism: at test-time, new entries are inserted with timestamps without immediate cross-item judgment; periodically, an offline batch process invokes the LLM to decide UPDATE / DELETE / IGNORE against existing entries. Crucially, both methods share the same architectural commitment—the LLM acts as both judge and operator—and consequently both apply destructive mutations (in-place vector overwrites and hard deletions) whenever the LLM's judgment so dictates.

**Decoupled Update.** Decoupled designs separate the LLM's role from the actual memory mutation. Zep [6], the representative example, restricts the LLM to emitting only categorical relation labels (e.g., *contradicts*, *duplicates*) over the new entry and a set of candidate existing entries; a deterministic system then performs the mutation by setting bi-temporal invalidation timestamps (*invalid_at*, *expired_at*) on the affected edges. This decoupling has notable architectural merits: edge bodies are preserved at the storage level (the mutation is non-destructive in that sense), and the execution layer is fully deterministic (eliminating randomness from the mutation step). However, the upstream LLM-emitted label remains the sole driver of system behavior. If the LLM mislabels a related-but-not-contradictory pair as *contradicts*, the deterministic system will faithfully invalidate the older edge; once set, the *invalid_at* field is not revisited downstream—rendering the misjudgment effectively irreversible at the retrieval layer.

**Shared structural limitation.** Whether the LLM acts as judge-and-operator (coupled) or as labeler (decoupled), proactive methods all share one structural property: the memory state for any given fact is bound to a single write-time LLM judgment. LightMem's own §5.6 discussion acknowledges this directly: *"an LLM might incorrectly interpret [related but not contradictory pieces] as a conflict and delete the older memory entry, leading to irreversible information loss"* [3, Sec. 5.6]. This vulnerability is amplified under constrained deployment, where smaller frozen LLMs produce lower-quality judgments yet still commit them irreversibly. The root cause lies not in the LLM's accuracy but in the architectural pattern itself.

We therefore argue for deferring KU resolution from a single write-time commit to query-time conflict resolution. In doing so, we look to the RAG literature, where query-time conflict resolution has been studied as a paradigm in its own right—and where mechanisms have been developed that we can adapt to the memory accumulation setting.

## 2.2 Knowledge Conflict Resolution in RAG

While query-time conflict resolution has not been systematically studied in the memory agent literature, it is an established paradigm in the broader Retrieval-Augmented Generation (RAG) community. Representative approaches operate by processing the retrieved candidate set at query-time—identifying which retrieved passages are consistent, which conflict, and which are irrelevant—before passing a refined context to the inference LLM.

**Cluster-and-separate at the passage level.** Astute RAG [17] is among the most explicit instantiations of this pattern. Its iterative knowledge consolidation procedure invokes an LLM to cluster consistent retrieved passages, separate conflicting passages into distinct groups, and filter irrelevant content. Within each consistency group, a candidate answer is proposed; the final answer is then selected based on source-aware comparison between LLM-internal knowledge and externally retrieved knowledge. The procedure can iterate multiple rounds until consolidation stabilizes.

**Triple-level conflict resolution.** TruthfulRAG [18] operates at a finer granularity. Rather than treating each retrieved passage as an atomic unit, it extracts (head, relation, tail) triples from retrieved content and constructs a query-aware knowledge graph. Conflict detection then operates over reasoning paths in this graph, using entropy-based filtering to identify which paths legitimately challenge the LLM's parametric beliefs. This approach demonstrates that fact-level triple representations provide a natural granularity for query-time conflict resolution—an observation we incorporate into our design.

**Shared field assumptions.** Despite mechanism differences, these RAG approaches share a common operational setting: each query triggers a single-shot retrieval round over a largely static corpus, and no persistent state is maintained across queries. Conflicts are typically inter-source disagreements that exist independent of any user's interaction history—e.g., contradictions between different sources, or between LLM parametric knowledge and external retrieval.

**Setting mismatch with memory accumulation.** Memory-augmented agents face a structurally different problem. The memory bank is not a static corpus but a continually growing repository of user-specific facts, where conflicts arise primarily from temporal drift of the same fact—i.e., the user updates information about themselves over time. Two implications follow. First, **what needs to be resolved is not which source to trust, but which version of the same fact is most recent**—introducing a temporal dimension that single-shot RAG methods do not address. Second, the persistent nature of memory means that resolution decisions at one query do not bind future queries; the latest-version judgment may need to differ depending on what each query asks.

We adapt the cluster-and-separate paradigm to the memory accumulation setting through two mechanisms: **identity grouping** identifies which retrieved candidates describe versions of the same fact (analogous to consistency clustering, but anchored on fact identity rather than information agreement); and **temporal resolution** selects the most recent version per group (replacing source-credibility selection with ingestion-time ordering). The combined effect is a query-time KU resolution mechanism that draws structural inspiration from RAG conflict resolution while addressing the temporal-validity nature of KU.

## 2.3 Knowledge Update Evaluation Benchmarks

To evaluate KU empirically, we adopt benchmarks from the long-term memory agent literature. These benchmarks can be broadly grouped into two categories, distinguished by conflict density and ground-truth annotation granularity, with implications for what aspects of a KU method they can effectively stress-test.

**User-information KU under sparse conflict.** A first category of benchmarks evaluates KU over user-specific facts—personal information, attributes, or life events that the user has stated and later revised. LongMemEval [9] establishes 78 KU questions across an extended dialogue history (~115K tokens), each targeting a single user-attribute change. MemBench [10] follows a similar design with its FM-ku subset, covering changes in user attributes over time. BEAM [11] introduces an Information Update ability across multi-domain dialogues at very long context lengths (up to 1M+ tokens). The structural commonality across these benchmarks is that **each query targets one specific fact change against an otherwise clean dialogue**: conflict density is low, and the remainder of the conversation provides only neutral context relative to the target fact. Consequently, these benchmarks primarily stress-test retrieval—whether the relevant pair of pre-change and post-change mentions can be retrieved—rather than KU resolution mechanisms once retrieval has succeeded.

**World-fact KU under high conflict density.** The FactConsolidation subset of MemoryAgentBench [7], hereafter FC, takes a different design choice. Its dialogues are constructed from MQUAKE [19] counterfactual edit pairs, in which a real-world fact (e.g., the head of state of a country, the language spoken in a region) is paired with an edited counterfactual version. FC composes these edits densely throughout the dialogue, such that the entire conversation forms what its prompt describes as *"a knowledge pool with lots of new facts."* Although the underlying facts are world-knowledge rather than user-specific, the KU resolution logic is structurally identical—the newer version supersedes the older—and the high conflict density places direct pressure on the KU resolution mechanism rather than on retrieval alone.

We adopt the single-hop subset of FactConsolidation (FC-SH) as our primary evaluation. Two considerations motivate this choice. First, **FC's high conflict density directly stress-tests the core contribution of our design**: the query-time identity grouping and temporal resolution mechanisms operate over many concurrent version pairs, exposing whether resolution remains accurate under load. Second, MQUAKE's counterfactual structure provides **fact-level ground truth**—each instance specifies the *gt_new* and *gt_old* triples explicitly—which enables fine-grained diagnostic attribution of failures across the pipeline (retrieval vs resolution vs inference). User-information KU benchmarks, by contrast, provide only QA-level ground truth, which conflates retrieval failure with resolution failure. Generalization of our method to user-information KU is left to future work.
